工作树是 Git 仓库的另一份检出，有自己的目录和分支。对话在工作树里干活，改的是那份副本：你自己检出里写了一半的东西不会被它动到，几个对话同时改一个项目也不会互相踩。

## 开对话时选

新对话的输入框上，项目和分支后面有一个「工作树」开关，项目是 Git 仓库时才有。点亮它再发第一条消息，这个对话就在一份新的工作树里开始。对话开始以后，就不能再挪进工作树了。

- 「设置 → Worktrees」里打开「新会话默认用独立工作树」，开关默认就是亮的，每次还能按次关掉。
- 工作树建在 `~/.lyra/worktrees`，你的仓库旁边不会多出目录。想放到别处，改同一页的「工作树根目录」。
- 这些对话在侧栏里照样归在原项目下，行上标着它在自己的工作树里。

工作树没建成时，这个对话直接在项目目录里运行，改动会落在你自己的检出里。输入框上分支后面会一直有一个琥珀色的标记，点开能看到原因。

## 合回 main，或者把 main 拿进来

工作树对话的输入框上方，那颗 chip 写着工作树的分支，后面是它和切出它的分支差多远：`↑2` 是领先两个提交，`↓1` 是落后一个。点开，菜单顶上写着它从哪个分支切出、领先落后几个、有几个文件没提交，下面是：

| 菜单里 | 做什么 |
| --- | --- |
| 合并到 main | 把这个工作树的提交合进 main |
| 从 main 同步 | 把 main 的新提交合进这个工作树 |
| 在访达中显示 | 打开工作树的目录（Windows 上是「在资源管理器中显示」） |

这里的 main 指切出这个工作树的那个分支，菜单上写的是它真实的名字。

- 合并和同步都要先把改动提交、等对话停下。做不了的时候，原因就写在那一项下面：「对话还在运行」「先提交 3 个文件的改动」「没有要合并的提交」「已经是最新」。main 正检出在别的工作树里，或者项目目录里有一个没做完的合并，也会被拒绝，菜单上写着是哪一种。
- 合并会冲突时立刻撤回，项目目录里不会留下合了一半的状态。菜单列出是哪些文件，提示你先从 main 同步、在工作树里解决，再合并。
- 同步停在冲突上时，菜单列出冲突的文件。可以「交给这个对话解决」：以你的名义发一条消息，让它解决冲突、保留两边各自的意图，再提交这次合并。也可以「放弃这次同步」。
- 合并成功后，菜单里给出「归档这个对话」。
- 合并和同步都只在本机做，不推送。

## 用完会收走

- 删除或归档一个对话，它的工作树目录跟着收走。分支上的提交全进了 main 的话，分支也一起删；没有的话分支留着，提交都在上面。
- 从归档里拿回来，会在原来的位置重新检出。
- 目录里有没提交的改动时，一律不收。删除确认框会写清楚留下了什么：几个文件没提交、留在哪个目录，哪个分支上还有几个提交没合并。

<Aside type="note">
旧版本建的工作树对话，各自成一个和项目同名的分组，副本建在仓库旁边。升级到 0.9.28 以后，启动时会把它们归回原项目下，文件树列得出来，也能从里面提交了。
</Aside>

对话做事时，也可能建议你另开一个会话、放进新工作树里去做，见[项目与会话](/docs/features/projects-and-sessions/#建议的新会话)。
