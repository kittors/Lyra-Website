Tell Lyra what you want in the composer. It works through the task with its tools and shows every step in the conversation.

## The composer

| Input | What it does |
| --- | --- |
| `/` | Built-in commands, your own commands, skills |
| `@` | Reference a file, folder, skill, agent or past chat |
| Drag, paste or `+` | Attach files and images — see [Attachments and panes](/en/docs/features/files-and-panels/) |
| Model name, and the reasoning effort beside it | Switch model and reasoning effort for this chat only |
| Bottom left | Switch the permission mode |

You can keep typing while a turn runs. New messages queue up and go out when the turn ends; **Send now** delivers one right away without interrupting the turn.

## Permission modes

| Mode | Behaviour |
| --- | --- |
| Ask for approval | Asks before every file write, command and network call |
| Auto approve (default) | Read-only commands run on their own; everything else still asks |
| Full access | Everything runs without asking |

When asked, you can **Allow once** or **Stop asking**; a command that has to run outside the sandbox only offers **Allow once**, and that is never remembered. Anything you've stopped being asked about can be taken back under Settings → Access. A request nobody answers is treated as a refusal after 5 minutes.

## Built-in tools

| Group | Tools |
| --- | --- |
| Files and code | `read` `write` `edit` `ls` `glob` `grep` `symbol` `lsp` |
| Commands | `bash` `bash_output` |
| Session and memory | `todo_write` `task` `skill` `rule` `recall` `learn` `ask_user` `request_credential` `list_credentials` |
| Network, preview, pictures and video | `web_fetch` `web_search` `preview` `image_generate` `video_generate` |

`image_generate` is only offered once you've added an image model — see [Drawing and editing pictures](/en/docs/features/images/) — and `video_generate` once you've added a video model.

`request_credential` asks you for a password, SSH key or token on a card. The value goes to Lyra, not the model: the model gets a name and uses the credential by that name in commands and the browser, and any output containing the value comes back masked. `list_credentials` lists names, kinds and where each may be used — never the values. Both are offered only where the card can be shown.

On top of these come the tools that drive the built-in browser, plus whatever your [MCP servers](/en/docs/features/mcp/) provide.

`web_search` works out of the box through keyless DuckDuckGo, but results are limited. For better search, add a key for Tavily, Brave or Exa under Settings → Web search — all three have a free tier.

## What shows up in replies

- **Markdown**: tables, code blocks and formulas (KaTeX) render as usual, and a `mermaid` block becomes a diagram. A code block, formula or table wider than the column scrolls sideways, with a thin scrollbar that appears under the pointer.
- **File links**: a local path shows as a file icon and its name. Click to open it beside the chat. Right-click to open it in the app chosen under Settings → General → Default file opener (Zed, Cursor or VS Code, say), pick another app, show it in the Finder (File Explorer on Windows), or copy its path or relative path.
- **File changes**: see which files a turn touched, review each diff, or undo the turn's direct edits. The file rows on the **N files edited** card and each file's title in the diff pane have the same right-click menu.
- **Tool calls**: the reads, edits and commands of a turn fold into one summary line that grows as calls land. Open it for one row per call; whatever the model says in between stays outside the fold. For the card layout, choose **Expanded** under Settings → Appearance → Tool calls.
- **Pictures**: with an image model set up, ask for a picture and it's drawn in the conversation — see [Drawing and editing pictures](/en/docs/features/images/).
- **Questions**: when the model is unsure, it asks you with a set of options. Even in Full access it won't answer for you.

You can edit and resend a message, or undo it. A turn that failed or was interrupted can **Carry on** from where it stopped. To try another direction without losing this one, fork it (below).

<Aside type="tip">
Want to ask something without disturbing the main conversation while it works? Press `⌥⌘S` (`Ctrl+Alt+S` on Windows and Linux) for a **side chat**. It can read the main conversation but never writes into it.
</Aside>

## Fork from here

Hover one of your own messages and click **Fork from here**, the last button in the row under it:

- A new conversation starts with everything before that message, titled "… (fork)".
- The message itself — text, images, attachments and referenced chats — goes back into the new conversation's composer, ready to edit and send.
- The original conversation is left exactly as it was. You can fork while a turn is still running, and a compacted conversation stays compacted in the fork.

<Aside type="caution">
The fork works in the same folder as the original. If both change files, they overwrite each other.
</Aside>
