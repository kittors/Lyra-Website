Lyra has no accounts and keeps none of your data for you: your sessions, settings and keys stay on your computer.

## Where things live

Everything user-level is in `~/.lyra` (on Windows, `%USERPROFILE%\.lyra`):

| Path | Contents |
| --- | --- |
| `settings.json` | Providers, models, MCP, permission mode and other settings — no API keys |
| `credentials.json` | API keys, and the Vault's passwords, SSH keys and tokens, encrypted |
| `vault.key` | The key that decrypts the file above |
| `forges.json` | Access tokens for code-hosting accounts, encrypted |
| `sessions/` | `sessions.db`, an SQLite database holding every conversation and what it spent; the `sessions.db-wal` beside it is part of it. If you upgraded from an older version, the old `.jsonl` logs stay here as a backup and are no longer read |
| `session-media/` | Pictures shown in conversations, including the ones drawn for you |
| `sidechats/` | Side chats |
| `memory.json` | Your personal memory, managed under Settings → Personalization |
| `projects/<id>/memory/` | What one project taught it: `learned.md` from the `learn` tool, and `MEMORY.md` from the optional background pass (off by default) |
| `worktrees/` | Conversations' own worktrees; move them under Settings → Worktrees |
| `skills/` `plugins/` `mcp/` `agents/` `rules/` `commands/` | Your skills, plugins, MCP bundles, agents, rules and slash commands |

In a project:

| Path | Contents |
| --- | --- |
| `.lyra/skills/` `agents/` `commands/` `rules/` `plugins/` | Apply to this project only; commit them with the repo |
| `.lyra/config.json` | Settings this project overrides; providers, keys and MCP aren't allowed here |
| `LYRA.md`, `AGENTS.md`, `CLAUDE.md` | Project instructions; the first one found in a folder wins |

## What leaves your computer

| Sent to | When |
| --- | --- |
| The model providers you configured | While chatting: messages, attachments, tool results |
| The search service you chose | When the agent uses `web_search`: the search terms |
| MCP servers you've switched on | When the agent calls their tools: the tool arguments |
| GitHub | Checking for and downloading updates |
| The plugin market | Browsing the catalogue and downloading what you install |
| Your code-hosting service | Reading and reviewing pull requests, with your token |
| Your phone | With mobile sync on: over your LAN, your reverse proxy or a relay |

Usage statistics are calculated on your machine and never uploaded.

## Keys

- Model provider API keys, the Vault's passwords and SSH keys, and code-hosting tokens are encrypted with AES-256-GCM into files with 0600 permissions; the decryption key is `vault.key` in the same folder.
- They're never written to `settings.json` and never synced to your phone.
- Keys you enter for MCP servers in Lyra are encrypted the same way.
- Commands the agent runs can't read `credentials.json` or `vault.key`: inside the sandbox they're refused outright, and in full access you're asked first, every time. How the Vault works is in [Vault and credentials](/en/docs/features/vault/).

<Aside type="caution">
The encrypted file and its key sit side by side, so anything that can read your home folder can decrypt them. If that matters to you, give your tokens a short expiry.
</Aside>

## Cleaning up

- **Archive** just moves a chat out of the sidebar. Its log and usage stay, and you can unarchive it any time.
- **Delete** by archiving first, then deleting under Settings → Archived chats. Deletion can't be undone, and the old `.jsonl` backup from an earlier version goes with it; what the chat spent still counts under Settings → Usage.
- **Clear by date** under Settings → Storage: pick a date range and the conversations last active in it are cleared whole. What they spent stays counted.
- **Memory** can be reviewed, deleted or cleared under Settings → Personalization.
